MASTER PROMPT — SUPER ADMIN PLATFORM DASHBOARD (FINAL, EXPANDED)

🧠 CONTEXT

This is a multi-tenant School Management Platform.



Multiple schools exist as independent tenants

Each school has:

Students

Parents

Staff

Academic data

Financial data

The SUPER ADMIN is the platform owner (not a school employee)

The database schema is largely finalized, but platform-level and governance-related tables may be added if required.

This task focuses on building a powerful, safe, auditable Super Admin dashboard.

🎯 OBJECTIVE

Design and implement a Super Admin dashboard that provides:



Complete visibility across all schools

Controlled ability to modify even sensitive academic and financial data

Strong safeguards to prevent misuse

Full auditability for compliance and accountability

This dashboard must behave like a “god-mode control panel with seatbelts”.

🧩 CORE SUPER ADMIN CAPABILITIES

1️⃣ School & Tenant Management

Create / update schools

View full school profile

Suspend, lock, archive schools

Assign plans / limits

Switch context between schools safely

2️⃣ Data Visibility (FULL ACCESS)

For the selected school, Super Admin can view:



Students

Parents

Staff

Classes & enrollments

Timetable

Exams & results

Attendance

Library

Hostel

Transport

Invoices & payments

Internal remarks & notes

Sensitive data must be masked by default.

3️⃣ DATA MODIFICATION POWERS (NEW – HIGH PRIVILEGE)

Super Admin IS ALLOWED to modify the following with strict controls:



✅ Student Marks

Modify individual subject marks

Modify grades / percentages

Recalculate totals

View original vs modified values

Mandatory reason required

✅ Attendance

Modify daily or period-wise attendance

Add / remove attendance entries

See who originally marked attendance

Mandatory reason required

✅ Financial Transactions

Modify invoice status

Correct amounts (only via adjustment records)

Mark payments as verified / reversed

Cannot silently overwrite original financial values

✅ Internal Remarks

Add, edit, or redact internal remarks

View who created original remarks

Remarks are versioned (history preserved)

🚨 SAFETY & GOVERNANCE RULES (NON-NEGOTIABLE)

🔒 Modification Guardrails

Every Super Admin modification must:



Require explicit confirmation

Require a reason/comment

Be logged immutably

Preserve original data (history)

Be visible to School Admin as “Super Admin override”

No silent edits. Ever.

📜 Audit Logging (MANDATORY)

All Super Admin actions must be logged:



Who (Super Admin identity)

What was changed

Old value → New value

Affected school

Timestamp

Reason

Audit logs must be:



Immutable

Filterable

Exportable (admin-only)

🔍 Change History / Versioning

For these entities:



Marks

Attendance

Financial records

Remarks

Maintain:



Original value

Modification history

Latest effective value

Users should be able to:



View change timeline

See who changed what and why
